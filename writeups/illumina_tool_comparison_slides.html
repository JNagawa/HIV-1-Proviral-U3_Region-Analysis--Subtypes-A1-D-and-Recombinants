FastQCfastp TrimmomaticKraken2

What was done

  • fastp vs Trimmomatic compared for trimming; FastQC gives the shared pre-trim baseline.
  • Both trimmers held to the same quality bar — sliding window 4:15, LEADING/TRAILING 3, MINLEN 50, AVGQUAL 15. so the comparison reflects the algorithms, not mismatched settings.
  • fastp run with --cut_right (to match Trimmomatic's window) and --dedup.
  • Kraken2 (16 GB standard DB) removes reads descending from human (9606) or bacteria (2); keeps viral + unclassified. host is the dominant contaminant in proviral seq.

Step 1 · Download & Quality Control

Challenges & resolutions

Kraken2 was declared in the environment but never actually invoked
Contamination filtering was effectively missing from the pipeline. Wired Kraken2 in as a real step after each trimmer, filtering host/bacterial reads by an ancestor-walk over the DB's own nodes.dmp (bash/awk, no external taxonomy tool).
Kraken2 database is not bundled by conda (~16 GB, >50 GB RAM)
Requires a separate download. Documented the exact source + build in kraken2_standard_16gb_db/SOURCE.md so it is reproducible.
fastp and Trimmomatic report different survival metrics (read count vs %)
Not directly comparable at face value. Recorded both native metrics and held the two tools to identical thresholds; the qualitative result (fastp retains substantially more) is robust.

Step 2 · Genome Assembly

Challenges & resolutions

SPAdes 4.x crashed with SIGILL (“Illegal instruction”) on every sample
Root cause: bioconda's default build needs AVX2/FMA, absent on this CPU. Pinned spades=3.15.5 (last pre-4.x release) — runs to completion.
SPAdes assembly quality is coverage-sensitive — and got worse after Kraken2
Only the deepest sample ever reached full length; removing ~45% of contaminated reads dropped it below the threshold too. Documented as a real finding: contamination removal can hurt de-novo depth. BWA (reference-guided) was unaffected.
SHIVER needed a manual LANL reference alignment, then hit a missing bc
(1) The LANL compendium alignment has no static URL — automated the retrieval with a documented curl recipe. (2) shiver_init quits because compute nodes lack bc — added bc to the environment (fix in progress; SHIVER re-run pending).

Step 3 · Multiple Sequence Alignment

Tools, configuration & results

MAFFT (L-INS-i) MUSCLEClustal Omega

What was done

  • Aligned HXB2 + the 4 sample consensus sequences with each tool.
  • MAFFT run as L-INS-i (--localpair --maxiterate 1000). the review's pick — highest base-pair accuracy on divergent A1/D, needed for precise U3 coordinate mapping.
  • MUSCLE pinned to classic 3.8; Clustal Omega with --force.
  • All three retained 5/5 sequences; MAFFT was also the fastest.
Coloured U3 alignment (MAFFT L-INS-i): HXB2 + 4 sample consensus, 453 columns; top band = per-column conservation. Runtime: MAFFT 79 s · MUSCLE 116 s · Clustal Ω 205 s.
Finding

MAFFT L-INS-i is the pick — the most accurate mode for divergent HIV and also the fastest here. The U3 is near-completely conserved across the 4 samples at the resolution the motif scan depends on.

Step 3 · Multiple Sequence Alignment

Challenges & resolutions

MUSCLE 5.3 crashed with SIGILL on this node
Same AVX2 hardware limitation as SPAdes. Pinned muscle=3.8* (no AVX2 requirement) — note its CLI differs (-in/-out vs v5's -align/-output).
MAFFT lowercases its output — downstream motif tools read that as “masked”
FIMO / MOODS treat lowercase as soft-masked and skip it, silently yielding zero hits. Forced the U3 extraction output to uppercase, so scanners see real sequence.

Step 5 · Subtype & Recombination Detection

Challenges & resolutions

jpHMM aborted on a shared-library version conflict
An inherited LD_LIBRARY_PATH shadowed a required GLIBCXX version. Fixed the library path in its wrapper so jpHMM loads the correct runtime.
IQ-TREE 2 refused ultrafast bootstrap on the small subset
Too few effectively-distinct sequences for UFBoot. Dropped -B 1000 for the comparison run; it is re-enabled for the full-cohort tree where bootstrap support is meaningful.
Binary-name drift: iqtree2 vs iqtree3
The unpinned package resolves to IQ-TREE 3 (different binary name). Pinned iqtree=2.* to match the review's cited version and the iqtree2 call.

Step 6 · U3 Extraction & Motif Mapping

Tools, configuration & results

SeqKit (U3)FIMOMOODS TFBSToolsgquadpqsfinder

What was done

  • Extracted U3 (453 bp, 5 seqs) from the MAFFT alignment, anchored to HXB2's own annotated LTR coordinates.
  • TFBS scanners (FIMO / MOODS / TFBSTools) use JASPAR 2024 PWMs for 6 TFs (NF-κB p65/p50, SP1, NFAT, AP-1, TBP); FIMO threshold 1e-4.
  • G-quadruplex — gquad applies regex rules on G-tract runs & loop lengths (four G≥3 tracts, short loops); pqsfinder runs an exhaustive, imperfection-tolerant search (tolerates bulges/mismatches) with a scoring model. Both scan the raw U3 — no PWM/database.
  • Each tool runs a positive control on HXB2's own U3 first.

Step 6 · U3 Extraction & Motif Mapping

Challenges & resolutions

A shared logging helper swallowed every tool's stderr into the timing file
Real errors were hidden and metrics read as “0 / n/a”. Fixed lib_compare.sh to time via date without redirecting the wrapped tool's stderr — errors now land in the right log.
A REPO_ROOT off-by-one broke 7 run-scripts; lowercase U3 gave 0 hits
Fixed the path resolution across all scripts, and uppercased the extracted U3 so FIMO/MOODS/TFBSTools no longer treat MAFFT's lowercase as masked.
JASPAR PWM sourcing & per-tool format quirks
Fetched JASPAR 2024 via its REST API (version-locked, reproducible); split matrices per-file for MOODS; corrected a seqkit grep -n pitfall that had matched nothing.
